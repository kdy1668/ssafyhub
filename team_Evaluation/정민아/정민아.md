### 1. 기획 아이디어 구상 및 아키텍처 파악

이번 주 주요 기획 회의를 통해 서비스 아이디어를 구체화하고, 멀티 에이전트 기반 인프라 자동화 서비스인 'DevLaunch'의 기획안을 확정함. 아울러 팀원이 설계한 전체 시스템 아키텍처의 구조를 파악함.

* **초기 아이디어:** 3D 아바타 기반 실시간 가상 피팅 위젯 (쇼핑몰 B2B SaaS).

* **최종 채택 기획 (DevLaunch):**
  
  * **목적:** 실전 경험이 부족한 주니어 개발팀의 기획/비즈니스 로직 부재, 인프라 구축의 벽, 협업 툴 세팅의 어려움 해결.
  
  * **핵심 비즈니스 모델:** 동적 손익분기점(BEP) 시뮬레이터를 통한 타당성 검증 및 대형 IT 교육기관 대상 라이선스 과금.
  
  * **멀티 에이전트 파이프라인 (LangGraph):** PO 노드(기획/BEP 검증), DevOps 노드(인프라 설계), Workspace 노드(협업 툴 연동), Reviewer 노드(오류 검수).

### 2. 회의록 작성 및 협업 체계 (Jira/Notion) 구축

아이디어 도출을 넘어, 팀이 즉시 개발에 착수할 수 있도록 기획의 뼈대를 문서화하고 체계적인 프로젝트 관리를 위한 협업 환경을 구축함.

* **아이디어 방향성 및 요구사항 문서화:** 난상토론 형태의 기획 회의 내용을 정리하여 제품 요구사항 정의서(PRD)의 초안을 작성함. 사용자 저니 맵을 통해 고객 경험 흐름을 구체화하고, 경제적 타당성 시뮬레이션 파트를 상세히 기록하여 개발 우선순위를 명확히 함.

* **WBS 기획 및 스크럼(Scrum) 초기 세팅:** 프로젝트 기한에 맞춘 주차별 마일스톤과 작업 분할 구조도(WBS)를 기획함.

* **[NEW] Jira 및 애자일 툴 사용법 학습:** 본격적인 스크럼 매니징을 위해 Jira 사용법을 집중적으로 숙지함.
  
  * 프로젝트 목표에 따른 **에픽(Epic)** 생성
  
  * 주차별 **스프린트(Sprint)** 보드 구성 및 백로그 관리
  
  * 프론트/백엔드별 세부 작업(Task) 티켓 발행 및 담당자 할당 등 실무적인 협업 툴 매니징 역량을 확보함.

### 3. AWS 및 클라우드 서버 집중 학습

프로젝트에서 DevOps 역할을 원활히 수행하고 시스템 아키텍처를 완벽하게 이해하기 위해, 클라우드 인프라 지식을 집중적으로 보완함.

* **AWS 코어 서비스 스터디:** 애플리케이션 호스팅을 위한 EC2, 정적 자원 및 백업을 위한 S3, 도메인 연결을 위한 Route 53 등 핵심 서비스의 역할과 동작 원리를 딥다이브함. BEP 시뮬레이터 기능 구현을 위해 클라우드 유지비(고정비/변동비) 산정 방식도 함께 학습함.

* **컨테이너(Docker) 기반 환경 이해:** 로컬 개발 환경과 실제 서버 환경의 불일치를 막기 위한 Docker 컨테이너화 개념을 복습함.

* **권한 및 보안 이슈 대비:** 실제 배포 환경에서 자주 발생하는 IAM 권한 부족 에러나 포트 충돌 문제를 방지하기 위해 Linux 기반의 서버 권한 관리와 AWS 보안 그룹 설정에 대해 학습함.

### 4. 팀 인프라 아키텍처 분석 및 DevOps 운영 준비

팀원이 설계한 시스템 아키텍처를 리뷰하고, 이를 바탕으로 안정적인 구동과 무중단 배포를 직접 운영할 수 있도록 데이터 흐름과 파이프라인 구조를 파악함.

* **초기 인프라 토폴로지 분석:** Python(FastAPI) 백엔드, React(Zustand, React Flow) 프론트엔드, PostgreSQL 데이터베이스가 AWS 상에서 어떻게 유기적으로 연결되는지 팀원의 설계도를 바탕으로 완벽히 분석하고 내 것으로 만듦.

* **CI/CD 무중단 배포 흐름 파악:** GitHub Actions를 활용한 자동 빌드부터, Docker 이미지 생성, EC2 인스턴스로의 무중단 배포로 이어지는 전체적인 배포 파이프라인의 논리적 흐름을 이해함.

* **IaC(Infrastructure as Code) 구조 리뷰:** DevLaunch 서비스의 핵심 기능인 '인프라 코드 및 배포 스크립트(.zip) 제공'을 이해하기 위해, 우선적으로 우리 팀의 배포 구조가 어떻게 코드로 템플릿화 될 수 있는지 분석함. 향후 발생할 수 있는 인프라 에러 상황에 대비한 트러블슈팅 매뉴얼의 뼈대도 함께 구상함.번주 한일을 정리해서 노션에 정리할 예정이야.
